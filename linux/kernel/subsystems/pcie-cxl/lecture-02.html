实验 02: 添加一个传统 PCI 设备

Part 1 · PCI Express 基础 · PCI 枚举与 sysfs 身份

原理

PCI 枚举：从总线扫描到 sysfs

Linux 启动时，PCI 子系统递归扫描每条 PCI 总线（从 bus 00 开始），在每个 device/function 位置读取 Vendor ID 和 Device ID 寄存器。如果 Vendor ID ≠ 0xFFFF，说明该位置存在一个 function。这就是 PCI 枚举 的基本机制。

每个被发现的 function 获得一个不变的 BDF 地址（Bus:Device.Function），并在 sysfs 中创建目录：

/sys/bus/pci/devices/0000:00:01.0/
├── vendor      → "0x1b36"
├── device      → "0x0005"
├── class       → "0x00ff00"
├── uevent      → 包含 PCI_ID=1B36:0005
├── modalias    → 驱动匹配键
└── config      → 二进制配置空间

BDF 地址结构

一个 PCI 层次地址由三个字段组成：

  • Bus (8 bits)：0-255。Bus 00 是根总线
  • Device (5 bits)：0-31。每个总线最多 32 个设备
  • Function (3 bits)：0-7。每个设备最多 8 个功能

在 QEMU q35 中，bus=pcie.0,addr=0x1 意味着 device=1, function=0。Linux 将其表示为 0000:00:01.0（domain 固定为 0000）。

PCI 枚举过程： Kernel: "Vendor ID ≠ 0xFFFF? → 创建 struct pci_dev" Bus 00 ├── Device 00, Func 0: Vendor=0x8086 → 创建 0000:00:00.0 (Host Bridge) ├── Device 01, Func 0: Vendor=0x1b36 → 创建 0000:00:01.0 (NEW! pci-testdev) ├── Device 31, Func 0: Vendor=0x8086 → 创建 0000:00:1f.0 (ISA Bridge) ├── Device 31, Func 2: Vendor=0x8086 → 创建 0000:00:1f.2 (SATA) └── Device 31, Func 3: Vendor=0x8086 → 创建 0000:00:1f.3 (SMBus)

实验指导

目标

在 q35 拓扑中添加一个 pci-testdev，验证 Linux 枚举到恰好一个额外的 PCI function，并读取其 sysfs 身份属性。

操作步骤

  1. 运行自动观察： 
    make verify-02
  2. 交互式探索： 
    make run-02
    在 guest shell 中： 
    lspci -nn
cat /sys/bus/pci/devices/0000:00:01.0/vendor
cat /sys/bus/pci/devices/0000:00:01.0/device
cat /sys/bus/pci/devices/0000:00:01.0/class
cat /sys/bus/pci/devices/0000:00:01.0/uevent

预期观察

  • lspci 显示 5 个 function（4 个芯片组 + 1 个 pci-testdev）
  • 新设备的 BDF 为 0000:00:01.0
  • Vendor = 0x1b36 (Red Hat/QEMU)，Device = 0x0005 (pci-testdev)
  • Class = 0x00ff00（非标准设备，无标准驱动绑定）

解释

一个 -device QEMU 选项 = 一个 PCI function = 一个 sysfs 目录。枚举不要求设备有驱动程序——只要有配置空间且 Vendor ID 有效，就会被枚举。

提示：注意 class code 0x00ff00 的含义——它是 QEMU 的测试设备 class，不是存储/网络/显示等标准 class。正是因为没有标准 class，所以没有标准驱动会绑定它。枚举 ≠ 绑定。
