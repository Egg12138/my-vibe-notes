实验 04: 配置空间头部解析

Part 1 · PCI Express 基础 · 直接读取 PCI 配置空间

原理

配置空间：设备的"身份证"

每个 PCI/PCIe function 都有 256 字节（PCIe 扩展到 4KB）的配置空间。前 64 字节是标准化头部，包含操作系统识别和配置设备所需的所有基本信息。

Linux 通过 sysfs 将配置空间暴露为二进制文件：

/sys/bus/pci/devices/0000:00:01.0/config

Type 0 vs Type 1 头部

偏移大小字段Type 0 (EP)Type 1 (Bridge)
0x002Vendor ID✓✓
0x022Device ID✓✓
0x081Revision ID✓✓
0x093Class Code✓✓
0x0e1Header Type0x000x01
0x10–0x2424BARs6 × 32-bit2 × 32-bit
0x184Bus Numbers—Pri/Sec/Sub

Header Type 字节（偏移 0x0e）的 bit 7 是多功能标志，bits 6-0 指示头部类型：0x00 = Type 0（端点），0x01 = Type 1（PCI-to-PCI bridge）。

小端字节序

PCI 配置空间使用小端序。例如 Root Port 的 Vendor ID 存储为 36 1b，实际值为 0x1b36。Device ID 存储为 0c 00，实际值为 0x000c。用 od 读取时要注意字节顺序。

Root Port 配置空间头部（前 64 字节 hexdump）： 00000000 36 1b 0c 00 07 05 10 00 00 00 04 06 00 00 01 00 |6...............| ├─────┘ ├─────┘ ├──┴──┘ ├──┘ Vendor Device Class Hdr 0x1b36 0x000c 0x060400 Type 1 00000010 00 00 80 fe 00 00 00 00 00 01 01 00 10 10 00 00 |................| └──BAR0──┘ ├──┴──┴──┘ Bus: Pri=0,Sec=1,Sub=1

实验指导

目标

直接用 od 读取配置空间的二进制 config 文件，解码关键字段，验证 Type 0 和 Type 1 头部的区别。

操作步骤

  1. 运行自动观察： 
    make verify-04
  2. 交互式探索： 
    make run-04
    在 guest shell 中： 
    # Root Port 前 64 字节
hexdump -C -n 64 /sys/bus/pci/devices/0000:00:01.0/config

# 读取 bus numbers（偏移 0x18 = 24 十进制）
od -An -tu1 -j 24 -N 4 /sys/bus/pci/devices/0000:00:01.0/config

# 端点前 64 字节
hexdump -C -n 64 /sys/bus/pci/devices/0000:01:00.0/config

预期观察

  • Root Port 第一个 dword：36 1b 0c 00 → Vendor=0x1b36, Device=0x000c
  • Root Port class bytes @ 0x08：00 00 04 06 → Class=0x060400 (PCI bridge)
  • Root Port header type @ 0x0e：01 → Type 1
  • Root Port bus bytes @ 0x18：00 01 01 00 → Primary=0, Secondary=1, Subordinate=1
  • 端点 header type @ 0x0e：00 → Type 0

解释

Type 1 头部（Root Port）比 Type 0 头部（端点）多了总线编号字段（0x18）。这就是内核如何发现拓扑层级的——通过读取每个设备的 Header Type 字节，内核知道该设备是终端设备（Type 0）还是桥（Type 1），从而决定是否继续扫描其下级总线。

关键认知：PCI 枚举的整个过程可以简化为：读取 Vendor ID → 非 0xFFFF → 读取 Header Type → Type 1 就扫描新总线 → 重复。不需要任何驱动程序或 ACPI 表就能完成。
