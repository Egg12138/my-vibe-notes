实验 09: CXL 拓扑 — Host Bridge, Root Port 与 Type 3 设备

Part 2 · CXL 内存语义 · PCIe 之上的内存协议层

原理

CXL 是什么

CXL (Compute Express Link) 是一组在相应 PCIe 代际物理链路上运行的协议，为数据中心工作负载添加缓存一致性和内存语义。它复用 PCIe 的链路、枚举和配置空间模型，但在同一条链路上定义三个职责不同的协议：

  • CXL.io：设备发现、配置、寄存器访问（本质上是 PCIe，用于枚举）
  • CXL.cache：主机 CPU 缓存与设备缓存之间的一致性协议（Type 1/2 设备）
  • CXL.mem：主机 CPU 直接访问设备内存的 load/store 协议（Type 3 设备）

CXL 设备类型

Type协议典型设备
Type 1CXL.io + CXL.cache智能网卡（无本地内存）
Type 2CXL.io + CXL.cache + CXL.memGPU、FPGA、加速器（有本地内存）
Type 3CXL.io + CXL.mem内存扩展器（本实验）

最小 CXL 拓扑

CXL 拓扑（QEMU 8.2）： Host CPU │ Root Complex (q35, bus 00) │ ├── 00:00.0 Host Bridge ├── 00:01.0 CXL Host Bridge (pxb-cxl, 1b36:000b, bus_nr=12) │ │ Class 0600 — PCIe 看来是普通的 Host Bridge │ │ CXL 看来是 CFMW 的入口点 │ │ │ └── 0c:00.0 CXL Root Port (8086:7075) │ │ Class 0604 — PCIe 看来是普通 Bridge │ │ CXL 看来是 CXL.io 下行端口 │ │ │ └── 0d:00.0 CXL Type 3 Memory Device (8086:0d93) │ Class 0502 — CXL Memory Device │ 256MB 易失性内存（RAM backing） │ └── 00:1f.x ICH9 芯片组（ISA、SATA、SMBus） 同时，Linux 还创建了 /sys/bus/cxl/： root0 → decoder0.0 (CFMW: 4GB @ 0x4f0000000) └── port1 → decoder1.0 └── endpoint2 → decoder2.0–2.3 (HDM decoders) └── mem0 (payload_max=2048, ram=256MB)

同一个 function 的两个视角

CXL 设备同时是两个子系统中的公民：

  • 在 PCI 子系统中，它们拥有 BDF 地址、配置空间和能力链表——lspci 能看到它们
  • 在 CXL 子系统中，它们拥有内存解码器、容量属性和区域管理——/sys/bus/cxl/ 暴露内存语义
核心洞察：CXL 不重新发明轮子。它使用 PCIe 用于设备发现、配置和 MMIO 寄存器访问（CXL.io），然后在其之上添加内存特定的协议（CXL.mem）。这种 "PCIe + 扩展" 的设计是理解所有 CXL 概念的关键。

发现与可用内存之间还有地址路径

发现 CXL 设备不等于已经获得可用内存。lspci 证明某个 PCI function 存在，/sys/bus/cxl/ 进一步证明内核识别出 CXL 拓扑和设备容量；但 CPU 能否以 load/store 访问这段容量，还取决于平台的 CFMW、从 root 到 endpoint 的 decoder 路径以及已创建的 CXL region。实验 10 专门检查这条尚未完成的地址路径。

实验指导

目标

构建最小 CXL 拓扑（一个 Host Bridge + 一个 Root Port + 一个 Type 3 内存设备），通过 lspci 和 /sys/bus/cxl/ 对比 PCIe 视角和 CXL 视角。

操作步骤

  1. 运行自动观察： 
    make verify-09
  2. 交互式探索： 
    make run-09
    在 guest shell 中： 
    # PCIe 视角
lspci -nn

# CXL 视角
ls -la /sys/bus/cxl/devices/

# CFMW（固定内存窗口）
cat /sys/bus/cxl/devices/decoder0.0/start
cat /sys/bus/cxl/devices/decoder0.0/size

# 内存设备容量
cat /sys/bus/cxl/devices/mem0/payload_max
cat /sys/bus/cxl/devices/mem0/ram/size
ls /sys/bus/cxl/devices/mem0/

预期观察

  • lspci：CXL Host Bridge (class 0600, 1b36:000b)、CXL Root Port (class 0604)、CXL Type 3 设备 (class 0502, 8086:0d93)
  • /sys/bus/cxl/devices/：10 个条目 — root0、port1、endpoint2、mem0、6 个 decoder
  • CFMW decoder0.0：start=0x4f0000000、size=0x100000000 (4GB)
  • mem0：payload_max=2048、ram/size=0x10000000 (256MB)、pmem/size=0x0

解释

class 0502 是 CXL Type 3 Memory Device 的 PCI class code。CXL Type 3 设备在 PCIe 层面是完全合法的 PCI function，但 class code 只提供粗粒度分类；CXL 能力、驱动和 CXL 总线对象才建立它的内存语义。其目标是通过 CXL.mem 向主机提供可寻址内存，前提是地址解码已被配置。CFMW (CXL Fixed Memory Window) 是平台固件（通过 ACPI CEDT 表）在物理地址空间中为 CXL 内存保留的一段连续区域。

提示：比较 lspci 中 class 0502 设备和 class 00ff00 (virtio-rng) 设备。两者都是 Type 0 header 的 PCIe 端点；前者会在 CXL 子系统中获得额外的能力和拓扑解释，而不是仅靠 class code 就自动变成可访问内存。
