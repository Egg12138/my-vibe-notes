实验 03: PCIe Root Port 与端点

Part 1 · PCI Express 基础 · 拓扑层级与总线编号

原理

从共享总线变成独立链路

传统 PCI 是共享总线：所有设备挂在同一条总线上，通过电气信号仲裁访问。PCIe 是点对点链路：每个设备通过独立的链路连接到上游。这意味着 PCIe 拓扑本质上是一棵树。

一条 PCIe Lane 不是共享的一根线：每条 Lane 都由一对发送差分线和一对接收差分线组成。因此链路可以全双工工作，主机向设备的请求与设备向主机的完成包可以同时传输。x1、x4、x8、x16 表示把多少条 Lane 并联成一条 Link；实际链路宽度和代际会在上电时由两端协商。

PCIe x4 Link：每个方向都有独立的 4 条 Lane Root Port TX ========> Endpoint RX 请求、写入 Root Port RX <======== Endpoint TX 完成包、中断消息 一条 Link 只连接两个相邻组件；Switch 或 Root Port 决定下一跳。

链路上电后，两端先进行 Link Training：发现对端、协商可用的宽度和速率、建立可靠传输状态。Linux 的 lspci -vv 在真实硬件上可显示 LnkCap/LnkSta；本实验主要观察训练完成后留下的拓扑结果，而不是测量链路电气信号。

分层：软件请求怎样变成在线路上传输的包

PCIe 不把一次读写表示成总线上的共享电平，而是把请求封装后逐跳发送。最常用的心智模型是三层：

层负责什么本讲对应的现象
Transaction Layer产生和解释 TLP：配置读写、MMIO 读写、完成包、消息。Linux 读取 Vendor ID 就是一笔配置请求。
Data Link Layer让相邻两端可靠交付：序号、LCRC、确认与重放；控制信息使用 DLLP。可靠性在每一跳处理，端点不需要直接面对整棵树。
Physical Layer链路训练、编码、串并转换与差分信号传输。把 TLP 分散到协商成功的 Lane 上。

TLP (Transaction Layer Packet) 是软件最应该关心的传输单位。它带有请求类型、地址或 BDF、长度和必要的属性；读请求不会立即携带数据，而由目标稍后返回 Completion TLP。这里的“包”是 PCIe 与传统 PCI 广播式总线模型最重要的差异之一。

路由：树中的包为什么能到正确设备

每条 PCIe Link 只看得到相邻两端，但 Root Port 与 Switch 的端口保存转发表或桥窗口，因而能把 TLP 转发到正确的下游。MMIO 请求按地址路由；配置事务则按 BDF（Bus:Device.Function）定位目标 function。BDF 是 Linux 中 0000:01:00.0 这种地址的后三段：domain:bus:device.function。

枚举时，Linux 从 bus 00 开始发送 Configuration Read，读取每个可能 function 的 Vendor ID。值不是 0xffff，说明那里有设备；若读到的是 Type 1 bridge，PCI 核心就根据桥的 primary/secondary/subordinate bus 范围扫描下游总线。Root Port 因而同时是物理链路的端点、TLP 的转发点，以及 Linux 看到的 Type 1 桥。

不要混淆两种“地址”：BDF 用来找配置空间中的一个 function；BAR 分配的 MMIO 地址用来访问该 function 暴露的寄存器。前者让 Linux 发现和配置设备，后者让驱动运行设备。

PCIe 拓扑 vs 传统 PCI 拓扑

树的节点类型：

  • Root Complex (RC)：树的根，连接 CPU 和 PCIe 世界。在 QEMU 中由 q35 机器类型提供
  • Root Port (RP)：RC 的下行端口。每个 RP 定义一条新的 PCI 总线。在配置空间中表现为 Type 1 header（PCI-to-PCI bridge）
  • Endpoint (EP)：树的叶子节点。在配置空间中表现为 Type 0 header
QEMU q35 PCIe 拓扑（本实验）： Root Complex (q35, bus 00) │ ├── 00:00.0 Host Bridge (8086:29c0) ├── 00:01.0 PCIe Root Port (1b36:000c) ← Type 1 Bridge │ │ │ └── 01:00.0 virtio-rng 端点 (1af4:1044) ← Type 0 Endpoint │ ├── 00:1f.0 ISA Bridge ├── 00:1f.2 SATA Controller └── 00:1f.3 SMBus Controller Root Port 创建了 Secondary Bus = 01 总线 01 上只有 01:00.0 这一个设备

总线编号与 sysfs 路径

Root Port 的配置空间中包含了三个总线编号：

  • Primary Bus：上游总线（bus 00）
  • Secondary Bus：桥的下行总线（bus 01）
  • Subordinate Bus：桥以下最高编号的总线（bus 01，因为下面没有更多桥）

Linux 根据这些信息构建 sysfs 中的设备拓扑路径：

/sys/devices/pci0000:00/0000:00:01.0/0000:01:00.0
                        └──Root Port──┘└──Endpoint──┘

路径的嵌套关系直接反映了 PCIe 的物理拓扑层级。

实验指导

目标

引入 PCIe Root Port 和端点，观察 PCI 总线编号扩展和 sysfs 层级路径。

操作步骤

  1. 运行自动观察： 
    make verify-03
  2. 交互式探索： 
    make run-03
    在 guest shell 中： 
    lspci -nn
cat /sys/bus/pci/devices/0000:00:01.0/secondary_bus_number
cat /sys/bus/pci/devices/0000:00:01.0/subordinate_bus_number
readlink -f /sys/bus/pci/devices/0000:01:00.0

预期观察

  • function count = 6（4 芯片组 + 1 Root Port + 1 端点）
  • Root Port：vendor=0x1b36, device=0x000c, class=0x060400 (PCI bridge)
  • Root Port：secondary_bus=1, subordinate_bus=1
  • 端点：vendor=0x1af4, device=0x1044 (virtio-rng)
  • 端点 sysfs 路径包含父桥 BDF：.../0000:00:01.0/0000:01:00.0

解释

Root Port 是一个 Type 1 PCI-to-PCI bridge。它创建了二级总线（bus 01），端点就在这条总线上被发现。sysfs 中的目录嵌套（而不是平铺）直接反映了物理拓扑层级 —— 这是理解更复杂 PCIe 拓扑的基础。

为什么这很重要：每个 Root Port 只能连接一个端点（PCIe 是点对点的）。要通过一个 RP 连接多个设备，需要在 RP 和端点之间加一个 PCIe Switch。Switch 是未来实验的主题。
