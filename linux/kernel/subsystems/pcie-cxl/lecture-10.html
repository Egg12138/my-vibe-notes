实验 10: CXL 解码器、内存设备与区域

Part 2 · CXL 内存语义 · HDM解码器层级与内存寻址模型

原理

CXL 内存寻址栈

CXL.mem 的内存映射遵循一个四层解码器模型，从上到下将系统物理地址 (SPA) 转换为设备物理地址 (DPA)：

系统物理地址 (SPA) │ ▼ CFMW (平台固件保留的地址窗口) │ ACPI CEDT 表定义 ▼ Root Decoder (主机桥级别) │ /sys/bus/cxl/devices/decoder0.0 │ 将 CFMW 拆分到各个 CXL Host Bridge ▼ Port Decoder (Root Port 级别) │ /sys/bus/cxl/devices/decoder1.0 │ 将范围拆分到各个下游端口 ▼ Endpoint HDM Decoder (设备级别) │ /sys/bus/cxl/devices/decoder2.* │ HDM = Host-managed Device Memory │ 将 SPA 范围映射到设备的内部 DPA ▼ CXL Region (可消费的内存) /sys/bus/cxl/devices/region* 内核创建用于表示可用的 CXL 内存

HDM Decoder 状态

每个 HDM decoder 有 4 个关键属性和一个状态生命周期：

属性含义
start解码器窗口在系统物理地址空间中的起始地址
size窗口大小（0 = 未编程/未提交）
committed0=暂存模式（未提交），1=已提交到硬件
locked0=可重新编程，1=锁定（热插拔后不改变）
target_type"expander" = Type 3 内存设备

解码器生命周期：枚举 (start=0,size=0) → 编程 (start=addr,size=N) → 提交 (committed=1)。提交后的解码器才能由 OS 使用。

枚举 ≠ 编程

这是本实验最重要的一条认知。实验 09 展示了 CXL 设备被枚举——我们知道它存在、知道它的容量。但枚举并不会自动创建可寻址的内存。编程序列是：

  1. 枚举发现设备容量（ram/size = 256MB）
  2. 固件或 OS 从 CFMW 中分配地址空间给 HDM decoder
  3. 将地址范围写入 decoder 的 start/size 寄存器
  4. 设置 committed=1 以激活映射
  5. 内核创建 CXL region 以表示可用内存

在本 QEMU + 内核组合中，HDM decoder 停留在步骤 1（未编程状态）。这是有意为之——它揭示了 CXL 内存是一个需要显式编程的两层协议，而不是一个即插即用的 I/O 设备。

实验指导

目标

深入检查 CXL 内存寻址栈的每一层：设备容量、HDM 解码器状态、region 状态和 CFMW 布局。验证枚举 ≠ 编程。

操作步骤

  1. 运行自动观察： 
    make verify-10
  2. 交互式探索： 
    make run-10
    在 guest shell 中： 
    # 设备容量（已知但未映射）
cat /sys/bus/cxl/devices/mem0/payload_max
cat /sys/bus/cxl/devices/mem0/ram/size
cat /sys/bus/cxl/devices/mem0/pmem/size

# 逐层检查解码器
cat /sys/bus/cxl/devices/decoder0.0/{start,size,locked}
cat /sys/bus/cxl/devices/decoder1.0/{start,size,locked}

# 端点 HDM 解码器（关键！）
for d in /sys/bus/cxl/devices/decoder2.*; do
  echo "$(basename $d): start=$(cat $d/start) \
size=$(cat $d/size) committed=$(cat $d/committed) \
target=$(cat $d/target_type)"
done

# CFMW 在 /proc/iomem 中
grep "CXL Window" /proc/iomem

预期观察

  • ram/size = 0x10000000（256MB）—— 设备容量是已知的
  • root decoder (CFMW)：start=0x4f0000000、size=0x100000000（4GB 已保留）
  • 端点 HDM decoders：start=0x0、size=0x0（未编程！）
  • CXL regions：不存在（没有已提交的解码器，就不可能有区域）
  • /proc/iomem：4f0000000-5efffffff : CXL Window 0（地址空间已保留但未映射到设备）

解释

平台已经为 CXL 保留了 4GB 的物理地址空间 (CFMW)，并且知道设备有 256MB 的 RAM 容量。但二者之间缺少了关键的连接——HDM decoder 还没有被编程。解码器的 start=0、size=0 说明设备尚未被分配 CFMW 中的具体地址范围。这就是 "枚举 ≠ 编程" 的含义：知道设备存在、知道它有多大距离"让 CPU 可以访问它"还差编程这一步骤。

在真实系统中：固件或 OS 会通过 CXL mailbox 命令对 HDM decoder 进行编程（设置 start/size → commit → 创建 region）。QEMU 8.2 的默认行为不自动编程 decoder，正好让我们观察这个关键的中间状态。
