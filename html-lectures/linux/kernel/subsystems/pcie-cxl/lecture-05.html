实验 05: BAR 与资源分配

Part 1 · PCI Express 基础 · 从配置寄存器到系统内存映射

原理

BAR 是什么

BAR (Base Address Register) 是 Type 0 PCI 配置空间中偏移 0x10–0x24 的 6 个 32-bit 寄存器。BAR 本身保存的是已分配的基地址和属性：它告诉软件这段资源是 Memory 还是 I/O、是否可预取、是否为 64-bit 地址，以及当前被放在 CPU 物理地址空间的哪里。

“设备需要多大空间”不是从 BAR 的普通当前值直接读出的。固件或 OS 在分配阶段会使用 BAR sizing 协议探测可写掩码，随后选择一个地址并写回 BAR。本讲不做这个探测，因为向真实工作的 BAR 写全 1 会暂时改变设备可见的地址；我们改读 Linux 已完成分配后的 resource 文件。

BAR 的编码方式

BAR 的低位是只读属性位，不是地址的一部分：

Bit含义
00 = Memory Space, 1 = I/O Space
2-1Memory BAR：00=32-bit, 10=64-bit
I/O BAR：保留
3Memory BAR：Prefetchable（可预取）
31-4基地址（4KB 对齐）

要得到基地址，需要 mask 掉低 4 位：base = raw_bar & ~0xf。

地址空间层级：分配与转发

Linux 的资源分配遵循桥窗口嵌套原则：

/proc/iomem（简化）： fe600000-fe7fffff : PCI Bus 0000:01 ← Root Port 的 MMIO 桥窗口 fe600000-fe600fff : 0000:01:00.0 ← 端点 BAR1（嵌套在桥窗口内） fea00000-febfffff : PCI Bus 0000:01 ← Root Port 的预取窗口 fea00000-fea03fff : 0000:01:00.0 ← 端点 BAR4/5（64-bit 预取）

桥窗口包含其下级设备的所有 MMIO 范围。CPU 访问落在窗口内的地址时，桥将事务转发到其下级总线。因而资源分配有两个相连的结果：endpoint 的 BAR 获得具体地址，Type 1 bridge 的窗口覆盖这些下游地址。实验 03 的树形拓扑在这里变成了树形的地址范围。

BAR sizing 机制

BAR 的大小通过写全 1 再读回来确定：size = ~(read_back_after_write_all_ones & ~0xf) + 1。但本实验不执行 BAR sizing（会破坏性地修改 BAR 值），而是通过 Linux 的 resource 文件间接获取 size。

实验指导

目标

解码三种典型 BAR（32-bit 非预取 × 2 + 64-bit 预取），验证 BAR 基地址与 Linux resource 分配一致，观察 /proc/iomem 桥窗口嵌套。

操作步骤

  1. 运行自动观察： 
    make verify-05
  2. 交互式探索： 
    make run-05
    在 guest shell 中： 
    # 读 Root Port BAR0（偏移 0x10）
od -An -tu4 -j 16 -N 4 /sys/bus/pci/devices/0000:00:01.0/config

# 读对应的 resource
cat /sys/bus/pci/devices/0000:00:01.0/resource

# 看 MMIO 空间布局
grep -E "fe[678a]" /proc/iomem

预期观察

  • Root Port BAR0 raw = 0xfe800000 → 低 4 位全 0 → 32-bit 非预取 memory BAR → base = 0xfe800000
  • resource[0] = 0xfe800000–0xfe800fff，size = 0x1000（4KB）
  • 端点 BAR1 raw = 0xfe600000 → 同类型 → base = 0xfe600000
  • 端点 BAR4 raw = 0xfea0000c → 低 4 位 = 0xc (1100) → 64-bit 预取 → 结合 BAR5 得 base = 0xfea00000
  • /proc/iomem 中端点范围嵌套在 Bus 0000:01 的桥窗口内

解释

BAR 的低 4 位是属性（类型、宽度、预取性），mask 后得到基地址。这个基地址由平台固件或 OS 在枚举时分配，不是设备固化的。Linux 通过 sysfs 的 resource 文件暴露分配结果。桥窗口包含下级设备的所有 BAR 范围，形成层级化的 MMIO 地址空间。

64-bit BAR 特殊处理：64-bit BAR 占用连续的两个 32-bit BAR 槽位（如 BAR4+BAR5）。写操作必须同时更新两个 32-bit 寄存器以确保原子性。BAR4 的低 4 位仍是属性位，BAR5 的所有 32 位都是地址的高位部分。
