RDMA 数据路径

从应用到 RNIC/Soft-RoCE 的完整数据搬运路径

分层模型

RDMA 数据路径从上层应用到物理网络共经过 5 层。理解每一层的边界和职责是掌握 RDMA 性能调优与故障排查的基础。

+-------------------------------------------------------------------+ | Application (用户进程, 调用 libibverbs / librdmacm) | | buffer = malloc(...); ibv_post_send(qp, &wr); ibv_poll_cq(cq, ...) | +------+------------------------------------------------------------+ | System Call (ioctl / write) —— uverbs 接口 +------+------------------------------------------------------------+ | User Library (libibverbs / provider: mlx5, rxe, bnxt_re) | | 将 WR 序列化为 WQE 格式, 写入共享内存环形队列 (doorbell) | +------+------------------------------------------------------------+ | uverbs —— /dev/infiniband/uverbsX +------+------------------------------------------------------------+ | Kernel RDMA Subsystem (ib_core / ib_uverbs / RXE / 厂商驱动) | | 对象管理, WQE 验证, DMA 映射, 网卡队列编程 | +------+------------------------------------------------------------+ | PCIe / 内核网络栈 +------+------------------------------------------------------------+ | RNIC / Soft-RoCE (硬件 HCA 或 RXE 内核模块) | | 数据搬移: DMA (硬件) 或 memcpy (RXE), 分组化, 发送到网络 | +------+------------------------------------------------------------+ | 物理层 (IB Link / Ethernet PHY) +------+------------------------------------------------------------+ | Network (InfiniBand fabric / Ethernet switch) | +-------------------------------------------------------------------+

各层职责

  1. Application — 运行在用户态的业务进程，分配缓冲区、通过 libibverbs 提交工作请求（WR）、轮询完成队列（CQ）获得操作完成通知。
  2. User Library — libibverbs 根据选择的 provider（如 mlx5 针对 Mellanox/ConnectX 网卡，rxe 针对 Soft-RoCE）将 WR 格式化为硬件可识别的 WQE，通过内存映射的环形队列提交给内核/硬件。
  3. uverbs — 用户态与内核态之间的控制通道。对象创建（QP、CQ、MR）等控制操作走 ioctl 或 write() 系统调用进入内核。数据路径（post_send / post_recv）走共享内存 + doorbell 机制，避免上下文切换。
  4. Kernel RDMA Subsystem — 内核中的 ib_core 模块管理所有 RDMA 对象。RXE 模块在此层完成软件数据拷贝。硬件厂商（mlx5、bnxt_re、irdma）的驱动负责直接编程 HCA。
  5. RNIC / Soft-RoCE — 数据的最终搬运者。硬件 RNIC 使用 DMA 引擎直接读写主机内存。RXE 使用 skb 走 Linux 内核网络栈发送数据。

控制面 vs 数据面

RDMA 架构将控制面和数据面清晰分离，这是它实现高吞吐低延迟的关键设计之一。

方面控制面 (Control Path)数据面 (Data Path)
典型调用ibv_alloc_pd(), ibv_create_qp(), ibv_modify_qp(), ibv_reg_mr()ibv_post_send(), ibv_post_recv(), ibv_poll_cq()
频率低频，建立连接时执行高频，每个消息的执行路径
延迟敏感度低（ms 级别可以接受）极高（us / ns 级别）
系统调用每次都经过系统调用通过 MMIO doorbell 避免系统调用
CPU 开销对象管理开销，可忽略直接决定应用性能上限
依赖资源内核对象、锁、内存分配DMA 引擎、PCIe 带宽、内存带宽
关键设计 数据面通过 mmap 将 HCA 的 doorbell 寄存器映射到用户空间，post_send 直接对 MMIO 区域写入即可触发网卡执行 DMA 读取 WQE。整个过程 零系统调用。

发送路径 (SEND)

应用通过 ibv_post_send() 提交 SEND WR 的完整执行流程：

  1. 准备缓冲区 — 应用填充数据到已注册的 MR 缓冲区，构造 ibv_send_wr 结构体，设置 opcode 为 IBV_WR_SEND，指定 sg_list 和 num_sge。
  2. 提交 WR — ibv_post_send(qp, &wr, &bad_wr) 被调用。在用户态，libibverbs 将 ibv_send_wr 转换为硬件 WQE 格式，写入 SQ 的共享内存环形缓冲区。最后写入 doorbell 寄存器通知 HCA 有新 WQE 可达。
  3. HCA 拾取 WQE — RNIC 检测到 doorbell，通过 DMA 从主机内存读取 WQE。对于 inline 发送，数据直接从 WQE 中读取；否则 HCA 需发起额外 DMA 读取数据缓冲区。
  4. 分组化 — HCA 将数据切分为 MTU 大小的包，添加 BTH、RETH（如果是 RDMA WRITE）等传输头。对于 RoCEv2，封装为 UDP/IP 包（目标端口 4791）。
  5. 发送到网络 — 物理层通过 IB link 或以太网 PHY 将数据包发送到网络中。
  6. 完成通知 — 数据被确认后（对 RC），或发出后（对 UD），HCA 将 WC 写回主机内存 CQ 中，并可选触发 MSI-X 中断。
  7. 应用轮询 — ibv_poll_cq(cq, num_entries, wc) 从 CQ 中取出 WC，检查 status 字段确认结果。

Soft-RoCE 发送差异

RXE 没有 DMA 引擎。当用户态调用 ibv_post_send() 时，WQE 通过 uverbs 系统调用进入内核。RXE 内核模块读取 WQE，通过 skb 和内核网络栈（通常是 UDP socket）将数据发出。数据的 memcpy 由内核 CPU 完成。

接收路径 (RECV)

  1. 预提交 RECV WR — 应用在通信开始前调用 ibv_post_recv(qp, &wr, &bad_wr) 将空缓冲区提交到 RQ。WQE 被推到硬件 RQ 环形缓冲区。
  2. 数据包到达 — RNIC 从网络收到数据包，解析 BTH 获取 destination QPN。根据 QPN 找到对应 QP。
  3. 匹配 WQE — HCA 从 RQ 头取一个 WQE（或由 SRQ 分配），对比数据包长度与 WQE 描述缓冲区大小。
  4. DMA 传输数据 — RNIC 通过 DMA 将 payload 写入 WQE 指定的 MR 缓冲区（使用 MR 的物理地址列表 PBL）。
  5. 生成 WC — HCA 将完成信息（opcode = IBV_WC_RECV, byte_len, src_qp, imm_data 等）写入 CQ。
  6. 应用获取数据 — 应用轮询 ibv_poll_cq() 获得 WC，使用 byte_len 判断实际收到数据量。处理完成后重新 post RECV 到 RQ。
常见陷阱 接收端必须 在数据包到达前 预提交 RECV WR。如果 RQ 为空，到达的 SEND 包会被 HCA 丢弃（RC 会重传，UC/UD 会静默丢失）。RQ 深度和 RECV 补充速度直接决定吞吐上限。

RDMA 单边路径 (WRITE)

RDMA WRITE 体现了 RDMA "远程直接内存访问" 的核心价值：完全不涉及对端 CPU。

  1. 发起方 构造 ibv_send_wr，opcode 设为 IBV_WR_RDMA_WRITE，指定：
    • 本地缓冲区 (sge.addr, sge.length) — 数据源
    • 对端虚拟地址 (wr.rdma.remote_addr) — 数据目的地
    • 对端 rkey (wr.rdma.rkey) — 远程访问凭证
  2. HCA 收到 WQE 后：读取本地数据 → 构造包含 RETH 的数据包 → 通过 RoCEv2/UDP 发送到对端。
  3. 对端 HCA 收到包后，验证 RETH 中的 rkey 是否有权写入该内存区域。验证通过后，对端 HCA 直接将 payload DMA 写入 host memory，无需对端 CPU 介入。
  4. 完成 — 数据到达对端内存后，对端 HCA 发回 ACK。发起方 HCA 收到 ACK 后生成 WC。对端无 WC（除非使用 WRITE_WITH_IMM）。
性能含义 单边操作消除了对端 CPU 的数据搬运开销。在存储场景（NVMe-oF）、AI 训练（NCCL）中，RDMA WRITE/READ 是 main path。但发起方需要知道对端的内存地址和 rkey，这通常需要通过带外通道（如 TCP 控制消息）预先交换。

Soft-RoCE 特殊性

Soft-RoCE (RXE) 是一个纯内核软件实现的 RDMA 数据路径。它与硬件 RNIC 有本质差异：

特性硬件 RNICSoft-RoCE (RXE)
数据搬移DMA 引擎，独立于 CPU内核 memcpy()，占用 CPU 周期
PCIe 带宽通过 PCIe 访问内存不需要 PCIe，但受内存带宽限制
CPU 卸载完全卸载CPU 做所有工作（数据拷贝 + 协议处理）
延迟1-3 us10-50 us（取决于速率）
数据面系统调用无（MMIO doorbell）每次 post_send 需系统调用
多队列硬件多队列，MSI-X 均衡单队列，或由内核调度分担
适用场景生产环境，低延迟要求学习、开发、测试、原型验证

RXE 数据路径的内部流程

当 RXE 作为 provider 时，ibv_post_send() 的用户态调用将通过 write() 系统调用进入内核。RXE 内核模块获取 WQE 后：

  1. 解析 WQE 中的 opcode、sge 列表等字段
  2. 读取用户态缓冲区（通过 copy_from_user 或 get_user_pages_fast）
  3. 根据 opcode 调用对应的处理函数（rxe_send(), rxe_rdma_write() 等）
  4. 构造 sk_buff，填充 BTH、RETH、IETH 等头部
  5. 通过内核 UDP socket 发送 skb（RoCEv2 UDP/4791）
  6. 对端 RXE 实例通过 UDP socket 接收包，解析头部，拷贝数据到目标 MR 的缓冲区，生成 CQ entry
RXE 性能边界 RXE 的数据路径 BW 上限取决于主机内存带宽和 CPU 频率，而非网络接口速率。例如，单核 3GHz CPU 的 memcpy 吞吐约 6-8 GB/s，这即为 RXE 的理论极限。多核也可线性扩展但受内核内存架构（NUMA）限制。SSD 或高速网络场景不要依赖 RXE 做基准。
