内存注册与 rkey

内存 pinning、lkey/rkey 访问控制与远端内存访问的安全模型

为什么需要注册内存

RDMA 绕过操作系统内核直接将数据从远端写入本机内存。这一特性要求：在发起 DMA 操作之前，目标内存区域必须已被 固定（pinned），即其物理页面不允许被内核换出。如果页面被换出，HCA（Host Channel Adapter）DMA 引擎将访问到错误的物理地址，导致数据损坏或系统崩溃。

注册内存时，内核完成以下步骤：

  1. 检查用户指定的虚拟地址区间，确认其属于调用进程的地址空间。
  2. 对该区间内所有虚拟页面执行 get_user_pages，将其固定到物理内存中（页面锁定）。
  3. 建立虚拟地址 → 物理地址的映射表，即 PBL（Physical Buffer List），或称 page list。
  4. 将 PBL 写入 HCA 硬件页表，使 HCA 能够直接将传入数据 DMA 到正确的物理地址。

硬件 DMA 引擎要求物理地址在传输单元内连续。对于大块内存，需要使用 Scatter-Gather List（SGL） 来应对非连续物理页面，或者提前分配 huge pages 以减小页表碎片。

ibv_reg_mr

ibv_reg_mr 是所有 RDMA 数据传输的基础——它创建并注册一个 Memory Region（MR），返回一个包含 lkey（本地 key）和 rkey（远端 key）的 ibv_mr 结构。函数签名如下：

#include <infiniband/verbs.h>

struct ibv_mr *ibv_reg_mr(struct ibv_pd *pd,
                           void *addr,
                           size_t length,
                           int access);
参数 说明
pd Protection Domain——MR 必须属于某个 PD，只有同一 PD 内的 QP 才能使用该 MR。
addr 待注册内存的起始虚拟地址，需按系统页面对齐（通常 4K）。
length 注册区间长度（字节）。
access 按位或的访问权限标志，控制 HCA 如何访问该内存。

访问权限标志

标志 含义 使用场景
IBV_ACCESS_LOCAL_WRITE 允许本机 HCA 通过 lkey 对该 MR 执行写操作。 几乎所有需要接收数据的 QP 都必须设置此标志。
IBV_ACCESS_REMOTE_WRITE 允许远端 HCA 通过 rkey 对该 MR 执行 RDMA WRITE。 服务端暴露写入缓冲区给客户端。
IBV_ACCESS_REMOTE_READ 允许远端 HCA 通过 rkey 对该 MR 执行 RDMA READ。 服务端暴露读取缓冲区给客户端。
IBV_ACCESS_REMOTE_ATOMIC 允许远端 HCA 对该 MR 执行原子操作（fetch-and-add / compare-and-swap）。 分布式锁、计数器场景。
IBV_ACCESS_MW_BIND 允许在该 MR 上绑定 Memory Window（用于动态撤销访问权限）。 需要对子区间做细粒度权限控制的场景。

如果不设 IBV_ACCESS_LOCAL_WRITE，即使你是本机也无法将数据写入该 MR——这意味着 ibv_post_recv 的目标缓冲区必须带有该标志。

lkey vs rkey

ibv_mr 包含两个 key：lkey（local key）和 rkey（remote key）。尽管二者通常数值相同，其语义完全不同：

属性 lkey rkey
用途 本机 HCA 访问本地内存 远端 HCA 访问本机内存
出现在 每个 ibv_sge 的 lkey 字段 每个 ibv_send_wr 中 rkey 字段（RDMA WRITE/READ/ATOMIC）
谁持有 本机进程内部使用 通过网络发送给远端节点
访问检查 HCA 校验 lkey 是否匹配 MR HCA 校验 rkey 是否匹配 MR，并检查 access flags

rkey 是一种 capability，而非完整的安全机制。任何获知 rkey 的远端节点都可以在对应 access flags 允许的范围内访问你的内存。rkey 不绑定 IP 地址或连接身份，因此 rkey 泄露等同于将该部分内存的读写权限拱手让人。

安全警告：不要将 rkey 记录到日志、调试输出或监控仪表盘中。rkey 是明文透传到远端节点的，网络上没有加密保护。在需要动态权限控制的场景，使用 Memory Window 替代直接暴露 rkey。

内存窗口（Memory Window）

Memory Window（MW）为 Memory Region 提供了动态、可撤销的访问控制。基本思路：

  1. 将一个较大的 MR 注册好（不设或仅设最小远端权限）。
  2. 为该 MR 分配一个 MW，MW 有自己的 rkey。
  3. 在需要时才将 MW 绑定到 ibv_bind_mw 指定的子区间，生成新的临时 rkey。
  4. 绑定完成后将 MW 的 rkey 发送给远端节点。绑定可被撤销，撤销后旧 rkey 立即失效。

Type 1 vs Type 2B MW

特性 Type 1 MW Type 2B MW
绑定方式 直接在 ibv_bind_mw 中指定窗口子区间 通过 send Work Request 绑定（IBV_WR_BIND_MW）
控制粒度 子区间 + 固定的 access flags 子区间 + 动态的 access flags
撤销 MW 被销毁时 绑定新的窗口或销毁 MW 时
适用场景 服务器端静态共享缓冲区 客户端临时授权访问特定数据段 
struct ibv_mw *ibv_alloc_mw(struct ibv_pd *pd, enum ibv_mw_type type);
int ibv_bind_mw(struct ibv_qp *qp, struct ibv_mw *mw,
                struct ibv_mw_bind *bind);

安全边界

RDMA 的安全模型建立在 "rkey 即权限" 的假设之上，这在生产环境中需要多重防护：

  • rkey 泄漏：若攻击者截获网络报文（RoCE 在以太网层无加密），可直接读取/写入目标内存。对策：使用 IPsec 或 MACsec 加密链路，或使用 iWARP 本身的加密能力。
  • 最小权限原则：只为确实需要的操作开启对应 access flags。例如只读场景不要加 IBV_ACCESS_REMOTE_WRITE。
  • 每连接独立 MR：为每个连接创建独立的 MR 和 PD，避免跨连接污染。
  • Trust Zone：RDMA 假定所有节点在同一 trust domain 内。跨 trust domain 的 RDMA 通信需要额外的安全隧道（如 TLS over RDMA 或使用使用加密的 NVMe-oF）。
  • cgroup RDMA 控制器：Linux 内核提供 rdma cgroup controller，可限制每个 cgroup 中 RDMA 资源（MR 数量、QP 数量）的使用上限，防止单一进程耗尽系统资源。

性能考量

ibv_reg_mr 是一个昂贵的操作。其开销来源于：

  • get_user_pages：遍历进程页表并逐页锁定，开销随注册大小线性增长。
  • PBL 构建：将物理地址列表填入 HCA 页表格式，需要内核态与硬件交互。
  • TLB 刷新：部分硬件在注册后需要刷新 IOMMU TLB。

优化策略

策略 原理 适用场景
Registration Cache 一次性注册大块内存，反复使用。不重新注册，只换用不同的子区间。 多数生产场景；但需注意 MR 内的访问边界由用户代码管理。
Huge Pages 使用 2M 或 1G 大页可大幅减少 PBL 条目数（减少 512 倍 vs 4K 页）。 大数据传输、数据库、存储服务器。
On-Demand Paging（ODP） 注册时不确定物理页面，由硬件在访问时触发缺页并固定。 避免预固定大块内存；但每次缺页引入延迟，不适合延迟敏感场景。 
/* 注册缓存模式：预分配 64 MB，反复使用 */
void *buf = mmap(NULL, 64 << 20, PROT_READ | PROT_WRITE,
                 MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB, -1, 0);
struct ibv_mr *mr = ibv_reg_mr(pd, buf, 64 << 20,
                                IBV_ACCESS_LOCAL_WRITE |
                                IBV_ACCESS_REMOTE_WRITE);

常见错误

错误 症状 原因 修复
注册区间过小 RDMA WRITE 写入超出 MR 范围导致 REM_ACCESS_ERR 注册时 length 小于实际传输数据长度 确保 addr + length 覆盖所有传输操作
遗漏远端写标志 RDMA WRITE 返回 IBV_WC_REM_ACCESS_ERR ibv_reg_mr 未包含 IBV_ACCESS_REMOTE_WRITE 检查 access 参数，确保包含所需标志
在途 WR 时注销 MR 硬件访问已释放的内存 → 数据损坏或 crash ibv_dereg_mr 在仍有未完成 WR 时被调用 确保所有 WR 已完成再进行 deregister
把 rkey 当身份认证 攻击者伪造 rkey 访问内存 rkey 不是加密凭据，不绑定源地址 使用 MW + 短有效期 rkey，或网络层加密
页对齐错误 ibv_reg_mr 返回 EINVAL addr 或长度未按系统页面大小对齐 使用 posix_memalign 或 mmap 确保对齐
关键提醒：rkey 是对 MR 的访问令牌，其安全性等价于一个明文口令。在分布式系统中，永远不要假设 rkey 是秘密——你应当在网络层加固（IPsec/MACsec）而非依赖 rkey 自身。
