#03 对象与类的生命周期

3.1 Object 与 ObjectClass —— 两个核心结构

/* include/qom/object.h:128 */
struct ObjectClass
{
    Type type;                                    /* 回指 TypeImpl */
    GSList *interfaces;                            /* 实现的接口链表 */
    const char *object_cast_cache[4];             /* 类型转换缓存 */
    const char *class_cast_cache[4];
    ObjectUnparent *unparent;                      /* 从 composition tree 移除时的回调 */
    GHashTable *properties;                        /* 该类的所有属性 */
};

/* include/qom/object.h:154 */
struct Object
{
    ObjectClass *class;    /* 指向类型对应的 ObjectClass ★ 必须是第一个字段 */
    ObjectFree *free;      /* 析构函数 */
    GHashTable *properties; /* 实例级别的属性 */
    uint32_t ref;          /* 引用计数 */
    Object *parent;        /* composition tree 中的父对象 */
};
C 语言 OOP 的关键技巧：class 必须是 Object 的第一个字段。 这保证了 Object 和其所有子类型（如 DeviceState）的指针可以安全地强制转换为 Object*。C 标准保证结构体首字段与结构体自身有相同的地址。

3.2 type_initialize —— Class 的诞生

Class 不是随 TypeInfo 一起注册就创建的。它是 懒初始化的 —— 第一次有人需要这个类型时（查找、实例化），才会调用 type_initialize()。 下面是完整的初始化流程：

type_initialize(ti) /* qom/object.c:336 */ │ ├─ [1] ti->class_size = type_class_get_size(ti) │ /* 如果 class_size==0, 递归取父类的 class_size */ │ ├─ [2] ti->instance_size = type_object_get_size(ti) │ /* 如果 instance_size==0 → 标记为 abstract */ │ ├─ [3] ti->class = g_malloc0(ti->class_size) │ /* 分配 Class 内存 */ │ ├─ [4] type_initialize(parent) /* 递归初始化父类型 */ │ ├─ [5] memcpy(ti->class, parent->class, parent->class_size) │ /* ★ 核心：从父类 memcpy 整个 vtable！ */ │ /* 这样父类的虚函数指针被子类自动继承 */ │ ├─ [6] 处理 interfaces │ ├─ 拷贝父类的 interface 实现 │ └─ type_initialize_interface() 初始化自己的接口 │ ├─ [7] ti->class->properties = g_hash_table_new(...) │ ├─ [8] ti->class->type = ti /* 回指 TypeImpl */ │ ├─ [9] 执行 class_base_init 链（从最远的祖先到最近） │ for parent in ancestors(root → self.parent): │ if parent->class_base_init: │ parent->class_base_init(ti->class, ti->class_data) │ └─ [10] ti->class_init(ti->class, ti->class_data) /* 覆盖虚函数指针，定义该类的行为 */

步骤 [5] 的 memcpy 是 QOM 继承机制的核心：

  • 子类的 Class 内存大小 ≥ 父类的 Class 内存大小（在 step [1] 中保证）
  • memcpy 把父类 Class 的 全部内容 复制到子类 Class 的起始位置
  • 如果父类的 class_init 设置了某个函数指针（如 realize = my_realize），子类自动继承了它
  • 子类的 class_init 可以做覆盖：dc->realize = my_sub_realize
class_base_init 的陷阱： 如果父类型在 class_init 中设置了一个字段（比如分配了一个 buffer）， 这个 buffer 会被 memcpy 到子类。父类的 class_base_init 应当 撤销 这些不应被继承的副作用。 大多数类型不需要 class_base_init —— 它是为少数需要感知 "被继承" 事件的类型设计的。

3.3 instance_init —— 实例的诞生

/* qom/object.c:421 */
static void object_init_with_type(Object *obj, TypeImpl *ti)
{
    if (type_has_parent(ti)) {
        object_init_with_type(obj, type_get_parent(ti));  /* ★ 先递归初始化父类型 */
    }
    if (ti->instance_init) {
        ti->instance_init(obj);      /* 调用该层的 instance_init */
    }
}

调用顺序：从根类型到最具体的类型（类似 C++ 的 constructor 链）。

TYPE_OBJECT → object_instance_init(obj) TYPE_DEVICE → device_instance_init(obj) TYPE_PCI_DEVICE → pci_device_instance_init(obj) TYPE_E1000 → e1000_instance_init(obj)

每个 instance_init 只初始化 自己那一层 的字段， 不对子类字段做任何假设。

完整的对象构造流程：

/* qom/object.c:496 */
static void object_initialize_with_type(Object *obj, size_t size, TypeImpl *type)
{
    type_initialize(type);            /* [1] 确保 class 已初始化 */

    g_assert(type->instance_size >= sizeof(Object));
    g_assert(type->abstract == false);
    g_assert(size >= type->instance_size);

    memset(obj, 0, type->instance_size);  /* [2] 清零整个实例内存 */
    obj->class = type->class;             /* [3] 设置 class 指针 */
    object_ref(obj);                      /* [4] ref = 1 */
    object_class_property_init_all(obj);  /* [5] 初始化 static properties */
    obj->properties = g_hash_table_new_full(...);
    object_init_with_type(obj, type);     /* [6] instance_init 链 */
    object_post_init_with_type(obj, type);/* [7] instance_post_init 链 */
}

3.4 设备的两阶段构造：init + realize

普通 QOM 对象在 object_initialize 后就 "可用" 了。 但 设备 (TYPE_DEVICE 的子类型) 多一个阶段：

Phase 1: object_initialize() /* 不可失败 */ ├─ 分配内存 ├─ instance_init 链 └─ 设置初始字段值 │ │ ← 此时设备还不能被 guest 使用 ▼ Phase 2: qdev_realize() / device_set_realized(true) /* 可以失败 */ ├─ 检查属性完整性 ├─ 调用 DeviceClass::realize() 回调 │ ├─ 映射 MMIO 区域 │ ├─ 注册 IRQ │ ├─ 创建子设备 │ └─ 失败时返回 Error └─ 标记 realized = true
为什么要分两阶段？
  • instance_init 没有 Error** 参数 —— 不能失败。只能做简单字段赋初值、创建子对象、设置属性默认值
  • realize 有 Error** 参数 —— 可以失败。分配硬件资源（MMIO、IRQ、定时器），这些操作可能因配置错误而失败
  • 这种设计也支持 设备自省 (device introspection)：可以先 instance_init 一个设备，读取其属性，而不真正 realize 它

3.5 高层 API：object_new

/* include/qom/object.h:633 */
Object *object_new(const char *typename)
{
    TypeImpl *type = type_get_or_load_by_name(typename, &error_fatal);
    return object_new_with_class(type->class);
}

Object *object_new_with_class(ObjectClass *klass)
{
    Object *obj = g_malloc(klass->type->instance_size);
    object_initialize_with_type(obj, klass->type->instance_size, klass->type);
    return obj;
}

object_new("virtio-net-pci") → 查找类型 → 分配内存 → instance_init 链 → 返回可用对象。

3.6 析构：instance_finalize + unref

object_unref(obj)
  ├─ obj->ref--
  ├─ if ref == 0:
  │    ├─ object_property_del_all(obj)
  │    ├─ instance_finalize 链 (从具体类型到根类型，反向)
  │    │    e1000_finalize → pci_device_finalize → device_finalize → object_finalize
  │    └─ g_free(obj)
  └─ return

finalize 调用顺序与 init 相反：最具体的类型先被析构（类似 C++ 的析构函数链）。
