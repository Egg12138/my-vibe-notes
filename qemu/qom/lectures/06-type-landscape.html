#06 QEMU 中的 QOM 类型全景图

QOM 不是只在几个设备中用 —— 它是 QEMU 的 骨架。几乎所有你能在 QEMU 中 "看到"的东西都是 QOM 类型。本讲绘制一张完整的 QOM 类型地图。

6.1 根类型：TYPE_OBJECT

/* include/qom/object.h:28 */
#define TYPE_OBJECT "object"

/* qom/object.c:2850 —— 根类型注册 */
static const TypeInfo object_info = {
    .name          = TYPE_OBJECT,        /* "object" */
    .instance_size = sizeof(Object),    /* 48 bytes 左右 */
    .class_init    = object_class_init,
    .abstract      = true,             /* 根类型总是抽象的 */
};

TYPE_OBJECT 是 QOM 类型树中 唯一没有 parent 的类型。 所有其他类型最终都继承自它。ObjectClass 定义了最基础的虚函数： unparent（从 composition tree 移除时的回调）。 Object 定义了 ref（引用计数）、parent（composition tree 父节点）。

6.2 TYPE_DEVICE —— 设备基类

/* include/hw/qdev-core.h:77 */
#define TYPE_DEVICE "device"
OBJECT_DECLARE_TYPE(DeviceState, DeviceClass, DEVICE)

struct DeviceClass {
    ObjectClass parent_class;            /* 继承 ObjectClass */

    /* 设备虚函数 */
    DeviceRealize realize;               /* ★ 最重要的回调 */
    DeviceUnrealize unrealize;
    DeviceReset legacy_reset;            /* deprecated, 用 ResettableInterface */
    DeviceSyncConfig sync_config;

    /* 元数据 */
    DECLARE_BITMAP(categories, DEVICE_CATEGORY_MAX);
    const char *fw_name;
    const char *desc;
    const Property *props_;
    bool user_creatable;
    bool hotpluggable;

    /* 总线关联 */
    const char *bus_type;               /* 该设备插在什么总线上 */
};

QEMU 中的所有硬件设备都是 TYPE_DEVICE 的子类型。 这包括 PCI 设备、SysBus 设备、I2C 设备、USB 设备等。TYPE_DEVICE 引入了 两阶段构造（instance_init + realize）、device category 分类、hotpluggable 标记、 legacy reset 等核心概念。

6.3 TYPE_BUS —— 总线基类

/* include/hw/qdev-core.h:318 */
#define TYPE_BUS "bus"
OBJECT_DECLARE_TYPE(BusState, BusClass, BUS)

struct BusState {
    Object parent_obj;
    DeviceState *parent;              /* 总线所属的设备 */
    const char *name;
    BusClass *parent_class_override;  /* 用于 hotplug handler */
};

Bus 的特殊之处：

  • 每个 Bus 实例都有一个 parent DeviceState（总线属于某个设备，如 PCI host bridge）
  • 每个 Device 都有一个 parent_bus（设备插入某条总线）
  • 设备树就是通过这个 Device ↔ Bus 的双向链接构建的

6.4 TYPE_SYS_BUS_DEVICE —— 系统总线设备

/* include/hw/core/sysbus.h:18 */
#define TYPE_SYS_BUS_DEVICE "sys-bus-device"
OBJECT_DECLARE_TYPE(SysBusDevice, SysBusDeviceClass, SYS_BUS_DEVICE)

struct SysBusDevice {
    DeviceState parent_obj;
    int num_mmio;
    struct {
        hwaddr addr;
        MemoryRegion *memory;
    } mmio[QDEV_MAX_MMIO];
    int num_pio;
    struct { ... } pio[QDEV_MAX_PIO];
};

SysBusDevice 是 数量最多的设备类型—— 它代表直接映射到系统地址空间的设备： UART、Timer、GPIO 控制器、中断控制器……这些设备通过 MMIO 或 PIO 与 CPU 交互。

6.5 TYPE_PCI_DEVICE —— PCI 设备

/* include/hw/pci/pci_device.h:9 */
#define TYPE_PCI_DEVICE "pci-device"
OBJECT_DECLARE_TYPE(PCIDevice, PCIDeviceClass, PCI_DEVICE)

struct PCIDevice {
    DeviceState qdev;                  /* 继承 DeviceState */
    /* PCI 配置空间 */
    uint8_t config[PCI_CONFIG_SPACE_SIZE];
    /* PCI BARs */
    MemoryRegion io_regions[PCI_NUM_REGIONS];
    ...
};

PCIDevice 的层次关系：TYPE_OBJECT → TYPE_DEVICE → TYPE_PCI_DEVICE → TYPE_E1000。 通过这种多层继承，e1000 自动获得了 DeviceState（id, realized, parent_bus）→ 再获得 PCIDevice（config space, BARs）→ 最后添加自己的 e1000-specific 字段。

6.6 TYPE_MACHINE —— Machine 类型

/* include/hw/boards.h:23 */
#define TYPE_MACHINE "machine"
OBJECT_DECLARE_TYPE(MachineState, MachineClass, MACHINE)

struct MachineClass {
    ObjectClass parent_class;
    const char *family;
    const char *desc;
    void (*init)(MachineState *ms);           /* 旧式 init */
    void (*setup_fw_cfg)(MachineState *ms);    /* firmware config */
    bool (*get_hotplug_handler)(...);
    ...
};

Machine 类型用于定义虚拟平台：-M virt 选择 "virt-machine" 类型， -M pc-q35-6.2 选择 Q35 芯片组的 x86 PC。Machine 的 init 回调 负责创建所有板载设备、CPU、内存映射。

6.7 TYPE_MEMORY_BACKEND —— 内存后端

/* include/sysemu/hostmem.h */
#define TYPE_MEMORY_BACKEND "memory-backend"
#define TYPE_MEMORY_BACKEND_RAM "memory-backend-ram"
#define TYPE_MEMORY_BACKEND_FILE "memory-backend-file"
#define TYPE_MEMORY_BACKEND_MEMFD "memory-backend-memfd"

MemoryBackend 负责管理 guest RAM 的分配策略：

  • memory-backend-ram：匿名 mmap（最常见）
  • memory-backend-file：文件 mmap（hugepage、DAX）
  • memory-backend-memfd：memfd_create（共享内存）

通过 -object memory-backend-ram,id=mem0,size=1G,share=on 创建。

6.8 TYPE_USER_CREATABLE —— 用户可创建接口

/* include/qom/object_interfaces.h:8 */
#define TYPE_USER_CREATABLE "user-creatable"

TYPE_USER_CREATABLE 是一个 接口类型，不是一个具体的类。 任何可以通过 -object 或 object_add 创建的对象都必须实现此接口：

  • memory-backend-*
  • cryptodev-backend-*
  • rng-*
  • sev-*

接口提供了 complete() 回调（类似 Device 的 realize，用于可失败的后初始化）。

6.9 Container 类型与 Composition Tree

/* include/qom/object.h:29 */
#define TYPE_CONTAINER "container"

/* qom/object.c:1672 —— root containers */
static const char *const root_containers[] = {
    "/objects",      /* -object 创建的东西在这 */
    "/machine",      /* Machine 和所有板载设备 */
    "/peripheral",   /* -device 热插拔设备 */
    "/peripheral-anon",
};
/ (root container) ├─ /objects │ ├─ mem0 (memory-backend-ram) │ └─ cryptodev0 (cryptodev-backend-builtin) ├─ /machine │ ├─ virt-machine │ │ ├─ cpu[0], cpu[1], ... │ │ ├─ gic (arm-gic-v3) │ │ ├─ uart0 (pl011) │ │ └─ pcie.0 (PCIe root complex) │ │ ├─ e1000.0 │ │ └─ virtio-blk.0 │ └─ ... └─ /peripheral └─ (热插拔设备)

info qom-tree 在 QEMU monitor 中展示的就是这棵 composition tree。

快速 grep：在 QEMU 源码中搜索所有 QOM 类型： 
grep -r 'TYPE_\w\+\s\+"' include/ | grep '#define TYPE_'
这列出了约 800+ 个 QOM 类型定义。

6.11 运行时观察类型树

# 启动 QEMU 后, 在 monitor 中:
(qemu) info qom-tree             # 查看 composition tree
(qemu) qom-list /machine         # 列出 /machine 下的子对象和属性
(qemu) qom-get /machine/uart0 type  # 查看 uart0 的类型名
(qemu) device_add edu            # 动态添加设备 (要求 user_creatable=true)
(qemu) object_add memory-backend-ram,id=mem1,size=512M  # 动态添加对象

类型作用是否可实例化
