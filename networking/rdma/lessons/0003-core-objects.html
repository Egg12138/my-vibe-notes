第三课 · Verbs 核心对象模型

深入理解 RDMA Verbs 编程模型中的五个核心对象及其生命周期

从文件 I/O 理解 RDMA 对象

如果你熟悉文件 I/O，可以类比理解 RDMA 对象模型。这种类比虽然不完全精确，但对初学者是非常好的思维脚手架：

RDMA 对象文件 I/O 类比说明
ibv_context文件描述符（fd）与 RDMA 设备交互的根句柄，创建其他所有对象的前提
ibv_pd文件系统命名空间资源隔离边界，MR 和 QP 必须属于同一个 PD 才能互访
ibv_mrmmap 映射区域注册后的内存区域，附带 lkey/rkey 作为访问凭证
ibv_cq异步 I/O 完成队列存放操作完成通知的环形缓冲区，类似于 Linux AIO 的 io_getevents
ibv_qpsocket 描述符通信端点，包含发送队列（SQ）和接收队列（RQ）

Context（ibv_context）

ibv_context 是设备句柄，通过 ibv_open_device() 获得。每个进程打开同一个设备会获得独立的 context。context 中保存了该进程与该设备交互所需的所有内核状态。

在同一进程中，可以打开多个 context（不同设备），但每个 context 都是独立的——你不能用 context A 创建的 QP 去 context B 的 CQ 上 poll 完成事件。

Protection Domain（ibv_pd）

ibv_pd 是 RDMA 的访问控制边界。一个 PD 中创建的 MR 只能被同一个 PD 中的 QP 使用。这确保了不同应用或不同租户之间的内存隔离。

可以这样理解：如果进程 A 和进程 B 各自有独立的 PD，进程 A 的 QP 就无法访问进程 B 的内存（即使进程 B 暴露了 rkey），因为它们的 MR 属于不同的 PD。

Memory Region（ibv_mr）

要让 RDMA 硬件访问一块内存，必须先注册它。注册过程做了三件事：

  1. Pinning（锁定） — 调用 get_user_pages() 将虚拟地址对应的物理页锁定在内存中，不允许被 swap 出去
  2. 地址映射 — 建立虚拟地址到物理地址的映射表（PTE），硬件 DMA 引擎需要物理地址
  3. 生成访问密钥 — lkey（local key）用于本地操作验证，rkey（remote key）发送给远端用于 RDMA READ/WRITE

注册完成后返回 ibv_mr 结构体，其中包含 lkey 和 rkey。

struct ibv_mr {
    struct ibv_context *context;  // 所属设备上下文
    struct ibv_pd *pd;            // 所属保护域
    void *addr;                   // 缓冲区虚拟地址
    size_t length;                // 缓冲区长度
    uint32_t lkey;                // 本地访问密钥
    uint32_t rkey;                // 远程访问密钥
};
注册成本 MR 注册是一个昂贵的操作：它涉及页表遍历、物理页锁定、DMA 地址映射建立。在性能敏感的代码中，应该一次性注册大块内存然后重复使用，而不是频繁注册/注销小块内存。生产环境中常用内存池 + 提前注册的策略。

Completion Queue（ibv_cq）

CQ 是 RDMA 异步完成模型的核心。它本质上是一个内核管理的环形缓冲区，存放 Work Completion（WC）条目。

关键设计：

  • 共享：一个 CQ 可以被多个 QP 共享（SQ 和 RQ 完成事件都投递到同一个 CQ）
  • 轮询语义：ibv_poll_cq(cq, max_wc, wc_array) 是非阻塞的。如果 CQ 为空，返回 0
  • 容量：CQ 的容量必须 >= 所有关联 QP 的 SQ + RQ 深度之和，否则可能溢出
  • 顺序保证：同一 QP 上的 WC 按提交顺序返回，但不同 QP 的 WC 可能交错

Queue Pair（ibv_qp）

QP 是 RDMA 通信的核心对象。每个 QP 包含两个独立的队列：

  • Send Queue（SQ） — 存放发送工作请求：SEND、RDMA WRITE、RDMA READ
  • Receive Queue（RQ） — 存放接收工作请求：仅 RECV

QP 类型决定了通信语义：

类型可靠性连接性典型用途
RC（Reliable Connection）可靠，有 ACK/重传一对一绝大多数生产应用
UC（Unreliable Connection）不可靠，无重传一对一实时音视频
UD（Unreliable Datagram）不可靠，无重传多对多控制消息、组播
SRD（Scalable Reliable Datagram）可靠无序多对多AWS EFA 独有

本课程主要关注 RC 类型，因为它提供了类似 TCP 的可靠有序传输语义。

Work Request（WR）与 SGE

WR（Work Request）是用户提交给 QP 的操作描述符。它描述了要做什么、数据在哪、以及完成后如何通知用户。

SGE（Scatter-Gather Element）描述了一个数据缓冲区：

struct ibv_sge {
    uint64_t addr;     // 缓冲区虚拟地址（必须来自已注册的 MR）
    uint32_t length;   // 数据长度
    uint32_t lkey;     // 该缓冲区对应 MR 的 lkey
};

一个 WR 可以包含多个 SGE，实现 Scatter（接收时分散到多个缓冲区）或 Gather（发送时从多个缓冲区收集数据）。

Work Completion（WC）的结构

WC 是操作完成后的证据。每次 poll_cq 返回一个 WC 条目：

struct ibv_wc {
    uint64_t wr_id;     // 用户提供的标识符，用于匹配 WR
    enum ibv_wc_status status;  // IBV_WC_SUCCESS 或错误码
    enum ibv_wc_opcode opcode;  // 完成的操作类型
    uint32_t qp_num;    // 产生此完成的 QP 编号
    uint32_t byte_len;  // 传输的字节数（仅 RECV）
    uint32_t imm_data;  // 立即数（WRITE_WITH_IMM / SEND_WITH_IMM）
};

wr_id 是连接 WR 和 WC 的纽带。你在提交 WR 时设置 wr.wr_id = my_tag；当 WC 返回时，通过 wc[i].wr_id 就能知道是哪个操作完成了。这是实现事件驱动状态机的关键。

创建与销毁顺序

RDMA 对象的创建和销毁有严格的依赖顺序：

创建顺序 (CREATE): [Context] ──→ [PD] ──→ [CQ] ──→ [MR] ──→ [QP] 1 2 3 4 5 销毁顺序 (DESTROY): [QP] ──→ [MR] ──→ [CQ] ──→ [PD] ──→ [Context] 5 4 3 2 1

规则很简单：先创建的先销毁。因为 QP 引用了 CQ（完成事件投递到这里），MR 引用了 PD（访问权限检查），所以销毁时必须反向进行。

理解依赖 写一个简单的 RDMA 程序时，最常见的 crash 原因就是资源释放顺序错误。例如，先销毁了 PD 但还有 MR 属于它，内核在尝试注销 MR 时访问已释放的 PD 会导致 use-after-free。始终遵循后进先出的销毁顺序。
