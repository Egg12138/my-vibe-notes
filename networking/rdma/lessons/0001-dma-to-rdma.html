第一课 · 从 DMA 到 RDMA

理解 DMA 的基本概念，以及 RDMA 如何将 DMA 扩展到远端

什么是 DMA？

DMA（Direct Memory Access，直接内存访问）是一种硬件机制，允许外设（如磁盘控制器、网卡、声卡）绕过 CPU，直接读写系统内存。

在没有 DMA 的时代，每次设备数据传输都需要 CPU 参与：CPU 从设备读取一个字节，再把它写入内存。这种方式称为 PIO（Programmed I/O）。当数据量小时还可以接受，但在高速网络或磁盘场景下，CPU 会被完全占满，无力处理应用逻辑。

DMA 控制器接管了数据搬运工作：CPU 只需要告诉 DMA 控制器"从哪里读、写到哪里、多少数据"，然后就可以去处理其他任务。DMA 控制器完成传输后通过中断通知 CPU。

关键认识 DMA 的本质是让数据传输操作从 CPU 卸载到专用硬件。这个思想也是 RDMA 的基石——只不过 RDMA 把范围从"本地设备 ↔ 本地内存"扩展到了"远端设备 ↔ 本地内存"。

DMA 的局限：只能在本机

传统 DMA 的传输范围被限制在 PCIe 总线内部。当数据需要跨越网络时，CPU 仍然必须介入：

  1. NIC 通过 DMA 将网络数据写入内核缓冲区
  2. CPU 将数据从内核缓冲区拷贝到用户缓冲区（一次 read() 系统调用）
  3. CPU 处理数据
  4. CPU 将数据从用户缓冲区拷贝到内核缓冲区（一次 write() 系统调用）
  5. NIC 通过 DMA 从内核缓冲区读取并发送

即使 NIC 使用了 DMA，数据在用户态和内核态之间的两次拷贝（以及对应的上下文切换）仍然会消耗大量 CPU 周期，增加延迟。这被称为 数据搬运瓶颈。

RDMA 的创新

RDMA（Remote Direct Memory Access）从根本上改变了数据路径。核心思想是：让远端 NIC 可以直接读写本机的内存，不需要本机 CPU 参与数据传输过程。

RDMA 与传统 socket 通信有三个根本区别：

特性传统 SocketRDMA
零拷贝数据在用户缓冲区和内核缓冲区之间至少拷贝两次NIC 直接从用户缓冲区 DMA 读取/写入，无需内核中转
内核旁路每次 send/recv 都是系统调用，涉及上下文切换数据面操作（post_send）通过 MMIO doorbell，无系统调用
单边操作远端 CPU 必须参与每次 recv 系统调用RDMA WRITE/READ 完全绕过远端 CPU，对端 CPU 零感知

深入理解 "零拷贝"

零拷贝不是说数据没有被拷贝，而是 不需要通过 CPU 做额外的中间拷贝。在 RDMA 中，数据只经过一条路径：应用缓冲区 ↔ NIC（通过 DMA 引擎）。而在传统 socket 中，数据路径是：应用缓冲区 → 内核 socket 缓冲区 → NIC，两次拷贝至少有一次由 CPU 完成。

"Remote" 的含义

RDMA 中的 "R"（Remote）指的是：远端 HCA（Host Channel Adapter）可以直接访问本地内存。

具体来说，当一个远端机器发起 RDMA WRITE 操作时：

  1. 远端 HCA 读取自身内存中的数据
  2. 远端 HCA 将数据打包成网络包
  3. 数据到达本机后，本机 HCA 直接将 payload 写入本机内存
  4. 本机 CPU 从未参与 数据写入过程

这是"远程 DMA"的真正含义：DMA 操作的目标地址在远端机器上，但数据搬运由本地 HCA 主动完成。

四种 RDMA 传输实现

RDMA 不是一个单一的协议，而是一族技术的统称。以下是主要的实现方式：

实现传输层特点硬件要求
InfiniBand原生 IB 协议无损 Fabric，原生 RDMA，最低延迟。有自己的物理层、链路层、网络层和传输层专用 IB HCA 和 IB 交换机
RoCEv2UDP/IPRDMA over Converged Ethernet，基于 UDP 封装（目的端口 4791）。需要无损以太网（PFC/ECN）支持支持 RoCE 的以太网网卡
iWARPTCPRDMA over TCP，可以在任何 IP 网络上运行。由 OS 提供传输层可靠性支持 iWARP 的网卡
Soft-RoCE (RXE)UDP/IP（软件）纯软件实现，内核模块模拟 RNIC 行为。没有 DMA 卸载，使用 memcpy + 内核网络栈不需要专用硬件，任何 Linux 机器即可

为什么本课程使用 Soft-RoCE

Soft-RoCE（也称为 RXE）是 Linux 内核中的一个纯软件 RDMA 实现。它通过内核模块模拟 RNIC 的行为，使用 UDP socket 封装 RDMA 协议。虽然它没有硬件 DMA 引擎带来的性能优势，但 RDMA 编程语义（Verbs API、MR 注册、QP 状态机、CQ 轮询等）与硬件 RNIC 完全一致。

选择 Soft-RoCE 的理由：

  • 零硬件依赖：任何一台 Linux 机器都可以运行，甚至可以用在两台虚拟机之间
  • 语义一致：学的就是标准 Verbs API，代码不经修改即可运行在真实 RNIC 上
  • 可调试：数据路径在内核中，可以通过 ftrace、tcpdump 等手段观察每个包的流转
  • 实验友好：本课程的 QEMU 实验环境内置了 RXE 模块
