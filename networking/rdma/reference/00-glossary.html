RDMA 术语表

核心概念速查，适合在阅读后续讲义与实验时随时对照

传输层

术语全称简要说明
RDMARemote Direct Memory Access一种允许网卡直接读写远程主机内存的网络技术，绕过 OS 协议栈和 CPU，提供极低延迟与高带宽。
InfiniBandInfiniBand从设计之初即为 RDMA 打造的全套网络体系，包含物理层、链路层、网络层和传输层规范。需要专用 HCA 和交换机。
RoCEv1RDMA over Converged Ethernet v1在以太网上承载 InfiniBand 传输层协议，使用 EtherType 0x8915，限制在同一 L2 广播域内，无法路由。
RoCEv2RDMA over Converged Ethernet v2将 InfiniBand 传输层封装在 UDP/IP (目标端口 4791) 中，可路由，是当前最广泛部署的以太网 RDMA 方案。
Soft-RoCE (RXE)Software RoCELinux 内核中的纯软件 RDMA 实现 (drivers/infiniband/sw/rxe/)，通过内核网络栈模拟 RNIC 行为，无需专用硬件。
iWARPInternet Wide Area RDMA Protocol在 TCP 之上实现 RDMA 语义，利用现有 IP 网络基础设施，但 TCP 开销导致性能低于 RoCE/IB。
OmniPathIntel OmniPath ArchitectureIntel 推出的专有互连架构，提供类似 InfiniBand 的高性能特性，已逐步退出市场。

核心对象

术语全称 / 解释
VerbsRDMA 编程接口的统称，由 InfiniBand 规范定义。libibverbs 是 Linux 上的标准实现。
Protection Domain (PD)安全隔离域，将 MR、QP、AH 等对象绑定在一起。同一 PD 内的对象可以互相访问，跨 PD 需要 rkey 授权。
Memory Region (MR)注册到 HCA 的连续虚拟内存区域，注册后获得 lkey (本地) 和 rkey (远程) 两个句柄用于访问。
Completion Queue (CQ)存放 Work Completion (WC) 的队列。Post-send/post-recv 操作完成后，CQ 会收到对应 WC 通知。
Queue Pair (QP)RDMA 通信的基本端点，包含 Send Queue (SQ) 和 Receive Queue (RQ) 两个子队列。QP 是发送/接收操作的执行单位。
Work Request (WR)应用层通过 ibv_post_send / ibv_post_recv 提交的操作请求。描述"做什么"（SEND/RECV/RDMA WRITE 等）。
Work Queue Element (WQE)WR 被提交到 QP 后，由硬件/驱动转化为 WQE 放入硬件队列。WQE 是硬件可执行的格式。
Work Completion (WC)WQE 执行完成后在 CQ 中生成的事件记录。包含 opcode、status、byte_len、source QPN 等信息。
Shared Receive Queue (SRQ)多个 QP 共享的接收队列，用于减少接收缓冲区预分配总量。适合大规模连接场景（如 MPI）。
Address Handle (AH)包含目的地 L3/L4 地址信息的数据结构，用于 UD QP 的每条 send 操作指定对端。RC QP 在 transition 时内置在 QP 上下文中。

QP 类型

类型全称特性
RCReliable Connection面向连接、可靠传输、保序。每个 QP 对应一个远端 QP。支持全部 opcode（SEND/RECV/RDMA WRITE/RDMA READ/ATOMIC）。
UCUnreliable Connection面向连接但不保证可靠。no ACK/retransmission。不支持 RDMA READ 和 ATOMIC。延迟更低，适用于可容忍丢包的应用。
UDUnreliable Datagram无连接、不可靠、不保序。一个 QP 可与任意多个远端的 QP 通信。最大 payload 受限于 MTU (通常 4096 bytes)。不支持 RDMA READ/WRITE/ATOMIC。
XRCExtended Reliable ConnectionRC 的扩展，允许接收端多个 QP 共享同一个 SRQ，减少接收端 QP 数量。主要用于 MPI 场景。
DCDynamic Connected面向连接但连接是动态建立的。发送时自动创建或复用连接，适合 HPC 中的大规模全通信模式。

操作类型

操作描述
SEND主动端将本地 MR 中的数据发送到对端。对端必须预先 post RECV WR。双方 CPU 均参与。
RECV被动端接收 SEND 数据。数据写入预先 post 的 RECV WR 指定的缓冲区。
RDMA WRITE主动端直接将本地数据写入对端 MR（需对端 rkey）。对端 CPU 完全不感知，属于单边操作。
RDMA READ主动端从对端 MR 读取数据到本地缓冲区（需对端 rkey）。仅 RC 支持。对端 CPU 完全不感知。
RDMA WRITE_WITH_IMMRDMA WRITE 的同时携带 4 字节 immediate data。对端会在 CQ 中收到一个 WC，含 immediate 值。
ATOMIC (Fetch-and-Add)原子加法操作。对端 MR 中的一个 64-bit 值 += operand。原值返回给发起方。仅 RC 支持。
ATOMIC (Compare-and-Swap)原子比较并交换。如果对端的值 == compare，则 swap 为新值。结果返回给发起方。仅 RC 支持。

连接管理

术语说明
RDMA CMRDMA Connection Manager，内核模块 rdma_cm.ko，负责建立和管理 RDMA 连接，抽象出地址解析、路由解析、连接建立等步骤。
librdmacm用户态库，封装 RDMA CM 的内核接口，提供 rdma_create_id()、rdma_connect()、rdma_listen() 等 API。
rdma_cm_idCM 通信标识符，绑定一个 ibv_qp 和相关地址信息。应用通过 rdma_cm_id 发起/接受连接。
Address Resolution将目标 IP 地址解析为 GID 或 LID，映射到具体的 RDMA 设备和端口。通过 rdma_resolve_addr() 触发。
Route Resolution确定从本地设备到目标设备的路径（在 InfiniBand 子网管理器中查路由表）。通过 rdma_resolve_route() 触发。

控制面接口

术语说明
uverbsLinux 内核为用户态提供的 RDMA 控制面接口，通过 /dev/infiniband/uverbsX 字符设备访问。本质是 ioctl 或 write() 系统调用。
ib_uverbs内核模块 (ib_uverbs.ko)，处理 uverbs 系统调用，在内核中创建/销毁/修改 RDMA 对象。
rdma-core用户态 RDMA 软件栈（开源），包含 libibverbs、librdmacm、libibumad、以及各厂商的 verbs provider (mlx5, rxe 等)。
libibverbs最基础的 RDMA 用户态库，提供 ibv_open_device、ibv_alloc_pd、ibv_post_send 等动词 API。
librdmacm连接管理库，基于 libibverbs 提供更上层的连接建立 API。
libfabricOpenFabrics Interface (OFI) 的参考实现，提供比 raw verbs 更通用的 fabric 抽象。HPC 应用 (MPI) 的底层传输抽象。
UCXUnified Communication X，UCSD 开发的高性能通信框架，在 libibverbs/libfabric 之上提供统一通信接口。UCC 是集合操作的扩展。

内存相关

术语说明
lkeyLocal Key，MR 注册时获得的本地访问密钥。在本地 QP post WR 时使用，标识本地缓冲区。
rkeyRemote Key，MR 注册时获得的远程访问密钥。对端在发起 RDMA WRITE/RDMA READ/ATOMIC 时使用。rkey 是安全凭证，但缺乏细粒度权限控制。
Memory Registration将应用缓冲区注册到 HCA 的过程，包括 pinning 内存页、建立 DMA 映射、生成 lkey/rkey。调用 ibv_reg_mr()。
Memory Pinning将虚拟内存页锁定在物理内存中，防止被 swap 出去。HCA 需要访问的是物理地址，pinning 确保物理页在 DMA 期间始终有效。
Physical Buffer List (PBL)描述 MR 对应的物理页帧列表。HCA 使用 PBL 进行 DMA 地址翻译，将虚拟地址转换为物理地址。
Memory Window (MW)基于已有 MR 动态创建的远程访问窗口，支持更灵活的 rkey 生命周期管理。典型用法：绑定后分成多个子窗口授予不同对端。

地址标识

术语说明
LIDLocal Identifier，InfiniBand 子网中由子网管理器分配的 16-bit 地址。每个 HCA 端口有一个 LID。RoCE 不使用 LID。
GIDGlobal Identifier，128-bit 类 IPv6 地址。RoCE 使用 GID 标识端口（基于 MAC 或 IPv6 生成）。
GRHGlobal Routing Header，RoCE/IB 跨子网时携带 GID 信息的路由头。RoCEv2 中 GRH 可省略或存在。
QPNQueue Pair Number，HCA 分配给每个 QP 的唯一编号。在 RC 中，远程端通过 QPN 定位通信对端。
PSNPacket Sequence Number，每个 RDMA 数据包的序号。RC 使用 PSN 实现可靠传输、丢包检测和重传。
SGIDSource GID，发起端 GID。RoCE 数据包头部携带的发送端 GID。
DGIDDestination GID，目标端 GID。RoCE 数据包头部携带的接收端 GID。

协议层

术语位置说明
InfiniBand Transport传输层定义数据包如何在 IB 子网中可靠/不可靠传输，包括分段、重组、流控等机制。
RoCEv2 (UDP/4791)传输层RoCEv2 数据包使用 UDP 封装，目标端口 4791，源端口为 QPN 的哈希。UDP 使得报文可被标准 IP 路由器转发。
BTHBase Transport Header每个 RDMA 数据包的必备头部。包含 opcode、destination QPN、PSN、分片标志等。
RETHRDMA Extended Transport HeaderRDMA WRITE/READ 操作的扩展头部。包含远程虚拟地址、rkey、DMA 长度。
IETHInvalidate Extended Transport Header携带 imm_data (4 字节) 的头，用于 WRITE_WITH_IMM 或 SEND_WITH_IMM。对端收到后 imm_data 作为 WC 的一部分返回。
AETHAcknowledgment Extended Transport HeaderACK/NACK 确认包中的扩展头部。包含确认 PSN、特征字段 ( Syndrome ) 表示错误类型。

性能相关

术语说明
Queue DepthQP 的 SQ/RQ 硬件队列深度，即可同时容纳的 WQE 数量。深度越大，CPU 与 HCA 间容忍的延迟越高，但占用内存也越多。
Selective Signaling选择性地为 WR 请求生成完成事件。信号 WR 会在 CQ 中产生 WC；无信号 WR 不产生 WC。通过 ibv_send_wr.send_flags & IBV_SEND_SIGNALED 控制。
Inline Send将小数据 (< 256B) 直接嵌入 WQE 中，避免 HCA 从内存中 DMA 读取。显著减少小消息延迟。
Zero-CopyRDMA 的核心优势：数据在 HCA 与用户缓冲区之间直接传输，无需中间拷贝（无需内核缓冲区，无需 socket buffer）。
MSI-X中断重定向机制。每个 CQ 可绑定独立的 MSI-X 中断向量，实现多核分摊 CQ 处理。配合 CPU 亲和性设置可显著提升性能。
Interrupt CoalescingHCA 合并多个完成事件后统一产生一次中断。减少中断频率，降低 CPU 开销，但会增加单次延迟。
